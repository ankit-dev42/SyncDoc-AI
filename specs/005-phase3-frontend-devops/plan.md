# Implementation Plan: Phase 3 — Frontend & DevOps

**Branch**: `005-frontend-devops` | **Date**: 2026-04-30 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `specs/005-phase3-frontend-devops/spec.md`

## Summary

Transform the SyncDoc AI frontend from a prototype into a production SPA with full routing, JWT authentication UI, React Query v5 server state, billing UI, coverage gates (JaCoCo 70% / Vitest 60%), and a GitHub Actions CI pipeline. Key decisions: `createBrowserRouter` for routing, Zustand + `sessionStorage` for auth state, a module-level Promise singleton in `client.ts` for safe concurrent 401 handling, React Query v5 object-syntax throughout, and a Maven `ci` profile that only activates the JaCoCo `check` goal to keep local builds unblocked.

## Architecture Decisions

### AD-1: createBrowserRouter over BrowserRouter wrapper

`createBrowserRouter` + `RouterProvider` is used in `main.tsx`. The legacy `<BrowserRouter>` wrapper is not used. This enables future data loaders without a breaking refactor. The route tree nests all authenticated routes under a `ProtectedRoute` layout element.

### AD-2: Zustand persist with sessionStorage (accessToken only)

The `accessToken` is persisted to `sessionStorage` using Zustand's `persist` middleware with `createJSONStorage(() => sessionStorage)`. The `user` object is in-memory only — it is reconstructed on tab open via `/api/auth/refresh` or login. This limits XSS token exposure to the current tab's session lifetime.

### AD-3: Refresh lock as module-level Promise singleton

```ts
// In client.ts — module scope, not React state
let refreshPromise: Promise<string> | null = null;
```

The 401 response interceptor:
1. Creates `refreshPromise` on the first 401 (if null)
2. All subsequent 401s attach `.then()` to the same promise
3. On resolve: all N queued requests retry with the new token
4. `.finally()` sets `refreshPromise = null` so future 401s start a new cycle

**Navigation from interceptor**: `client.ts` calls `navigateTo('/login')` using a handler registered by `main.tsx` after router creation (`setNavigationHandler(router.navigate)`). This avoids circular imports between `client.ts` and React Router.

### AD-4: React Query v5 object syntax — no positional args

All `useQuery` and `useMutation` calls use the v5 object syntax:
```ts
// ✅ v5 correct
useQuery({ queryKey: ['presence', workspaceId], queryFn: () => presenceApi.list(workspaceId) })

// ❌ v4 syntax — forbidden
useQuery(['presence', workspaceId], () => presenceApi.list(workspaceId))
```

### AD-5: JaCoCo check in ci profile only

The `prepare-agent` and `report` goals remain in the main build (always runs, no impact). Only the `check` goal (which fails the build on coverage drop) lives in the `ci` Maven profile. This unblocks local TDD by not failing `mvn test` during the red phase.
