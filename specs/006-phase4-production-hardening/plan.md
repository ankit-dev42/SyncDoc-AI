## Architecture Decisions

### 1. Testcontainers: BOM + shared static container

**Decision**: Add `testcontainers-bom` to `<dependencyManagement>` so all TC artifacts are version-aligned. Use a `static` `PostgreSQLContainer<?>` in `AbstractIntegrationTest` so Docker starts once per JVM, not once per test class. Subclasses inherit the container and the `@DynamicPropertySource` override automatically.

**Why not `@DataJpaTest` + H2**: H2 does not support `JSONB` (V7 migration), PostgreSQL-specific index expressions (V8), or `gen_random_uuid()` (V1). Tests against H2 would give false confidence.

**Why not per-class containers**: Per-class startup adds 3–5 seconds per `@SpringBootTest` class. With 3 IT classes, that's 15 seconds overhead vs. ~4 seconds with a shared container.

### 2. Failsafe plugin for `*IT.java` separation

**Decision**: Add `maven-failsafe-plugin` with `<includes>**/*IT.java</includes>` bound to the `integration-test` + `verify` phases. This ensures `mvn test` (Surefire, CI fast loop) never starts a Docker container. Only `mvn verify` (CI full suite) triggers Testcontainers.

### 3. logstash-logback-encoder via `logback-spring.xml`

**Decision**: `logback-spring.xml` (Spring-aware) allows `<springProfile>` conditionals. The `!local` appender uses `LogstashEncoder` which auto-includes all MDC entries as top-level JSON properties — no custom serializer needed. The `local` appender uses a colored pattern for developer readability.

**Sensitive field rule**: `AuditLogger` is the single write-path for all audit MDC entries. It enforces a static deny-list of forbidden MDC key names. Verified by `AuditLoggerStructuredOutputTest` at unit test time.

### 4. Actuator security rule ordering

**Decision**: In `WebSecurityConfig.filterChain()`, the new `hasRole("ADMIN")` rule for `/actuator/**` is inserted AFTER the existing `permitAll()` block (which covers `/actuator/health` and `/actuator/info`) and BEFORE `anyRequest().authenticated()`. Spring Security evaluates rules top-to-bottom; first match wins — so health/info remain public.

```java
.authorizeHttpRequests(authz -> authz
    .requestMatchers("/api/auth/**", ..., "/actuator/health", "/actuator/info").permitAll()
    .requestMatchers("/actuator/**").hasRole("ADMIN")   // ← new rule
    .anyRequest().authenticated()
)
```

### 5. ENTERPRISE authorize() method

**Decision**: Add `authorize(String userId, int currentSyncCount)` to `SyncAuthorizationService`. It wraps the existing `evaluate()` with an ENTERPRISE short-circuit:

```java
public AuthorizationResult authorize(String userId, int currentSyncCount) {
    UserSubscription sub = subscriptionService.forceRefreshFromStripe(userId);
    if (sub.getTier() == SubscriptionTier.ENTERPRISE) {
        return AuthorizationResult.ALLOW;
    }
    AuthorizationDecision decision = evaluate(userId, currentSyncCount);
    return decision.authorized() ? AuthorizationResult.ALLOW : AuthorizationResult.DENY;
}
```

`forceRefreshFromStripe()` is called for ALL tiers in `authorize()` — no: it's called only for ENTERPRISE (as clarified in Q3). PRO and FREE go through Redis-cached `evaluate()` unchanged.

**Corrected logic**:
```java
public AuthorizationResult authorize(String userId, int currentSyncCount) {
    UserSubscription sub = subscriptionService.getSubscription(userId);
    if (sub.getTier() == SubscriptionTier.ENTERPRISE) {
        subscriptionService.forceRefreshFromStripe(userId); // bypass cache
        return AuthorizationResult.ALLOW;
    }
    AuthorizationDecision decision = evaluate(userId, currentSyncCount);
    return decision.authorized() ? AuthorizationResult.ALLOW : AuthorizationResult.DENY;
}
```

### 6. CollaborationHealthIndicator conversion

**Decision**: Add `implements HealthIndicator` to the existing class and implement `health()`. The `@RestController` at `/api/v1/health` is retained as a backwards-compat endpoint. Actuator auto-discovers `@Component` beans implementing `HealthIndicator` — no explicit registration needed.

**Redis HealthContributor**: Spring Boot auto-configures `RedisHealthIndicator` when `spring-boot-starter-data-redis` is on the classpath. No code change needed — just expose it by adding `redis` to the health details in `application.yml`.
