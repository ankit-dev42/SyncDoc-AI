## Summary

Phase 2 makes the application functionally complete for core paid features. It replaces
five stubs with real implementations — Stripe billing, Redis subscription caching, OpenAI
documentation extraction, complete Project CRUD, and webhook idempotency — and corrects
five database schema gaps via Flyway migrations V7–V11. The primary technical approach
is async delegation everywhere external I/O is involved, with Redis as the distributed
cache layer and Spring AI as the model-agnostic OpenAI abstraction.

## Architecture Decisions

### Decision 1 — Stripe SDK: Static Initialisation + Interface Boundary

**Choice**: Set `Stripe.apiKey` once in the `StripeClientImpl` constructor. Keep all
SDK calls behind the existing `StripeClient` interface for mockability.  
**Rationale**: The Stripe library is not Spring-managed. A static key assignment in a
`@Bean` constructor is the idiomatic pattern. The interface boundary means tests never
touch the real SDK.  
**Consequence**: `LocalStripeClientStub` must implement two new interface methods.

### Decision 2 — Redis: Single `RedisTemplate<String, Object>` Bean

**Choice**: One `RedisTemplate<String, Object>` with `Jackson2JsonRedisSerializer<Object>` serves all cache domains.  
**Rationale**: Avoids proliferation of typed `RedisTemplate` beans. Keys are namespaced
by prefix (`subscription:`, future `feature-flag:`) to prevent collisions. Serialiser
stores clean JSON with no class metadata — safe on refactors.  
**Consequence**: Deserialisation requires `objectMapper.convertValue(cached, UserSubscription.class)` at the read site.

### Decision 3 — Spring AI: `ChatClient` + Classpath Prompt Template

**Choice**: Inject auto-configured `ChatClient` bean; load prompt from `classpath:prompts/extraction.st` via `PromptTemplate`.  
**Rationale**: Model-agnostic — swap OpenAI for Anthropic by changing only the starter dependency. No magic strings in Java source (Constitution Principle I).  
**Consequence**: `spring-ai-bom:1.0.0-M6` must be added to `<dependencyManagement>` in `pom.xml`.

### Decision 4 — Hibernate 6 Soft Delete: `@SQLRestriction` + `@SQLDelete`

**Choice**: `@SQLRestriction("deleted_at IS NULL")` on `Project`; `@SQLDelete(sql = "UPDATE projects SET deleted_at = NOW() WHERE id = ?")` to redirect `deleteById`.  
**Rationale**: `@Where` is deprecated in Hibernate 6.3+. `@SQLRestriction` is the canonical replacement. Combined with `@SQLDelete`, no changes are needed to `ProjectRepository` or service methods.  
**Consequence**: A physical delete requires a custom `@Modifying` query if ever needed for GDPR purge.

### Decision 5 — @Async Exception Handling: try-catch in Method Body

**Choice**: Explicit `try-catch(Exception e)` inside `@Async` method bodies.  
**Rationale**: `AsyncUncaughtExceptionHandler` cannot access the `eventId` or `docId`
context without ThreadLocal gymnastics. The in-body catch is simpler and more explicit.  
**Consequence**: Every `@Async` method in Phase 2 must have a try-catch — enforced in code review via constitution compliance check.

### Decision 6 — OpenAI Retry: spring-retry `@Retryable`

**Choice**: `@Retryable(maxAttempts = 3, backoff = @Backoff(delay = 1000, multiplier = 2.0))` on `OpenAIExtractionClient.extractDocumentation()`.  
**Rationale**: Declarative retry via AOP; no boilerplate loop; testable by mocking the method to throw N times. `spring-retry` + `spring-aspects` are the minimal dependency pair — both are Spring-ecosystem libraries with no transitive bloat.  
**Consequence**: Add `@EnableRetry` to a `@Configuration` class (e.g., `AsyncConfiguration`).

### Decision 7 — Async Executor: Named Bounded `ThreadPoolTaskExecutor`

**Choice**: A named `ThreadPoolTaskExecutor` bean `"aiExtractionExecutor"` with `corePoolSize=10`, `maxPoolSize=10`, `queueCapacity=100`. Webhook dispatcher uses Spring's default `@Async` executor (already configured).  
**Rationale**: Bounded queue prevents memory exhaustion on bursty load. A dedicated named executor for AI work allows independent tuning without affecting webhook dispatch threads.  
**Consequence**: `@Async("aiExtractionExecutor")` annotation on the AI processing method; `POST /api/v1/ai/extract` returns 503 if the queue is full (thrown by the executor's rejection handler).
